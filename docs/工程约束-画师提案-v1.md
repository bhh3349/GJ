## 一、终端与脚本约束（含实测证据）

### 1.1 本机环境实测

| 项 | 实测结果 |
|---|---|
| Node / npm | `v22.22.0` / `10.9.4` |
| Git | `2.56.0.windows.1` |
| PowerShell | 只有 **Windows PowerShell 5.1**（`pwsh` 7 **未安装**） |
| Git Bash | 已安装：`C:\Program Files\Git\bin\bash.exe`，**但不在 PATH**（`Get-Command bash` 为空） |
| npm script-shell | 未配置（`null`） |
| 工作区 | 无 `.git`、无 `package.json` |

**npm 跑 scripts 用的是什么 shell（实测）**：

```
> node scripts 探针（scripts: "whichshell": "echo shellprobe=$0"）
$ npm run whichshell      → shellprobe=$0        # 原样输出 → 走的是 cmd.exe
$ npm run posix           → 'test' is not recognized as an internal or external command
$ npm run posix --script-shell=bash → npm error enoent spawn bash（bash 不在 PATH）
```

**结论**：在本机，`npm run` 默认走 **cmd.exe**，且当前配置下**无法**切到 bash。这意味着
**package.json 里任何 POSIX 写法（`rm -rf`、`cp`、`VAR=x cmd`、`test -f`）在本机必挂**。

### 1.2 三条硬约束（全组适用）

1. **交互式终端统一 Git Bash**：`&&`、`rm`、`cp`、`grep`、环境变量前缀可直接用，与后续 Linux/Docker 部署语义一致；本机已装。
   ⚠️ Windows PowerShell 5.1 **不支持 `&&`**（无 pwsh 7），用 PS 交互时会踩坑。
2. **npm scripts 必须跨平台**：只允许 `node scripts/xxx.mjs` / `vite` / `tsc` / `concurrently` / 纯二进制命令。
   - 删目录 → `rimraf`，跨平台环境变量 → `cross-env`，复杂逻辑 → 落成 `scripts/*.mjs` 由 Node 执行。
   - 这条不是为了好看：CI 和 Docker 是 Linux，本机是 cmd.exe，只有这写法两边都能跑。
3. **不写 `.npmrc` 的 `script-shell`**：实测 `--script-shell=bash` 直接 ENOENT；写死绝对路径会让别人机器和 CI 全挂。

## 三、知识库与文档体系（"是否接入知识库"的正面回答）

### 3.1 v1 不接向量知识库 / RAG

理由（针对本项目规模，不是通用结论）：
- 本项目语料是 **5～8 份 Markdown**，总量几十 KB，远低于需要检索的量级；全量塞进上下文比检索更准、更便宜、更少出错。
- RAG 会引入 embedding 服务、切片策略、召回质量三个新的不确定性来源，与「3 周、单人部署、SQLite 零运维」的定位冲突。
- 真正的问题是**文档会不会漂移**，不是**检索得够不够快**。

**替代方案：文件即知识库 + 契约单一事实源。**

### 3.2 目录结构（建议全组冻结）

```
C:\WorkSpace\sub
├─ AGENTS.md                  # 唯一 AI 上下文入口（见 §四）
├─ README.md                  # 给人看：启动方式、端口、目录说明
├─ .gitattributes / .editorconfig / .gitignore / .env.example
├─ docs/
│  ├─ 需求文档-v1.0.md
│  ├─ 需求文档-v1.1.md         # 需求唯一事实源（PM 维护）
│  ├─ api-contract.md         # ★ 接口唯一事实源（管家维护，画师/路由者只读）
│  ├─ decisions/              # ADR：每个待拍板项一条，记「结论 + 理由 + 影响面」
│  ├─ 技术选型.md
│  └─ 工程约束-画师提案-v1.md   # 本文
├─ scripts/                   # 跨平台 Node 脚本（不写 shell）
├─ src/gateway/               # 路由者
├─ src/api/ + src/db/         # 管家
└─ web/                       # 画师
```

**三条防腐规则**：
1. **契约先行**：`api-contract.md` 里没有的字段，前端不许自己造、后端不许私自加；要加先改文档再改代码。
2. **ADR 留痕**：v1.1 里 P1–P11 这类拍板，落 `docs/decisions/NNN-*.md`，避免两周后没人记得为什么这么定。
3. **文档过期即 bug**：代码变更连带更新对应文档，写进 Definition of Done（见 §4.5）。

### 3.3 什么时候才该上知识库

若后续出现「多地部署 + 多人协作 + 语料超过几百份文档」，再考虑；届时优先 MCP 方式接（而非自建向量库）。**v1 明确列为非目标。**

## 四、AI 开发守则（基于公开规范的落地版）

检索来源：
- `AGENTS.md` 规范（Linux Foundation / Agentic AI Foundation 托管，60k+ 项目采用；核心语义是「**离被编辑文件最近的 AGENTS.md 生效**」，纯 Markdown、无必填字段）
- Claude Code 官方最佳实践与 memory 文档：`CLAUDE.md` **每个会话都加载**，因此只放「适用范围广」的内容；官方明确警告 **文件过长会导致规则被忽略**，判断标准是「删掉这行会不会让 AI 犯错，不会就删」

### 4.1 单一入口，禁止多份文档互相抄

- 根目录 `AGENTS.md` 是**唯一**入口；`CLAUDE.md` 只写一行 `@AGENTS.md`（官方支持 import），**不重复内容**。
- 子目录如需差异规则（如 `web/AGENTS.md`），只写**差异项**，不重抄根文件。

### 4.2 `AGENTS.md` 草案（建议落地内容，保持 ≤ 60 行）

```markdown
# 项目：LLM 网关路由系统
Node 22 + Fastify + TypeScript + SQLite；前端 React + Ant Design（深色）；网关 :4000 / 管理后台 :4001。

## 命令
- 安装：npm ci
- 全量校验：npm run verify        # lint + typecheck + test + build，提交前必过
- 开发：npm run dev:gateway / dev:web
- 禁止在 package.json 里写 shell 语法（本机 npm 走 cmd.exe），复杂逻辑放 scripts/*.mjs

## 约定
- 金额=分(int)、token=int、时间=ISO8601 UTC；错误体：/v1/* 用 OpenAI 格式，/api/* 用 {code,message}
- 接口字段以 docs/api-contract.md 为唯一事实源，未定义字段不得自造
- UTF-8，换行 LF，2 空格缩进（见 .editorconfig）
- 提交信息用 Conventional Commits（feat/fix/docs/refactor/test/chore）

## 硬规则（违反即返工）
- CRITICAL: 上游 key 与网关 key 明文永不落盘、永不进日志；列表只回后 4 位
- CRITICAL: 前端禁止 mock 兜底数据；接口挂 → 错误态，无数据 → 空态。生产构建里不得出现任何假数据
- 前端禁止使用原生 <select> 与浏览器默认弹窗；统一用 AntD 深色组件
- 网关热路径禁止同步 DB 写

## 完成定义（DoD）
lint ✅ typecheck ✅ 相关测试 ✅ 构建通过 ✅ 契约文档同步更新 ✅ 有可复现的验证证据（命令输出/截图）
```

### 4.3 用「可验证信号」闭环，而不是靠自觉

官方最佳实践证明最关键的一条：**给 AI 一个能跑的检查**，否则它只能靠「看起来做完了」停手。

- 后端：`npm run test` + `npm run typecheck`
- 前端：`npm run build`（体积门禁）+ `tsc --noEmit` + 关键页 E2E/截图对比
- 统一入口：`npm run verify`，并挂到 **pre-commit hook / Claude Code Stop hook**，让它成为确定性门禁而非口头约定

### 4.4 工作流：先探索/规划，再写实现

- 跨文件、契约相关、需求有歧义的改动 → **先出计划再动手**；单行修复直接改，不套流程。
- 契约有疑问 → 先问「管家」，禁止「按猜的字段先写，回头再改」。

### 4.5 DoD（Definition of Done，全组统一）

一个任务算完成，必须同时满足：
1. lint / typecheck / 测试 / 构建全绿；
2. 有**可复现证据**（命令与输出、或界面截图），不靠口头"已通过"；
3. 契约文档（`api-contract.md`）与代码一致；
4. 前端改动需在真实接口下自测（禁止用 mock 证明自己完成了）；
5. 提交信息符合 Conventional Commits。

## 五、前端专属工程约束（画师侧）

### 5.1 目录与分层

```
web/
├─ src/api/         # 唯一出网层：按 api-contract.md 手写的类型化 client，统一错误码处理
├─ src/features/    # 按页面域组织：upstreams / keys / groups / models / stats / logs / dashboard
├─ src/components/  # 跨页复用组件
├─ src/theme/       # 深色主题 token（颜色/间距/圆角/层级），禁止页面里写魔法值
└─ scripts/         # 构建体积检查等 Node 脚本
```

- 页面**不得**直接 `fetch`；一律走 `src/api/`，便于统一注入鉴权、错误码映射、loading/重试。
- 契约未定期间只做：脚手架、路由、主题 token、布局骨架、空/错误态组件（与我上一轮承诺一致）。

### 5.2 状态与实时

- 每页四态齐全：`loading / empty / error / success`，写操作按钮进 loading 并给出成功/失败反馈（失败展示后端 `message`，`code` 用于分支提示）。
- 实时看板走 WS `{code, message}` 之外的既定协议；断线指数退避重连 + 重连后全量补刷；**QPS 等指标必须用后端给的时间窗口字段**，前端不拿本地时间猜。
- 长任务（模型同步、批量查余额）显示**真实进度**，禁止假进度条。

### 5.3 性能门禁（对应验收「首屏 < 2s」）

- 路由级分包；ECharts / AntD 重型模块按需引入，不进首屏主包。
- `npm run build` 后检查产物体积，超阈值直接失败（写入 `verify`）。
- 首屏 LCP 目标 ≤ 1.2s，验收线 < 2s；用真实后端数据测量，不测 mock 页面。
