# 7. API 契约 v1.0 冻结与 C1–C5 裁决（提案）

- 状态：**提案（Proposed，待 PM 拍板）**
- 日期：2026-10-06
- 提案者：管家 · 管理后端
- 拍板者：PM（尚未裁决）

## 背景与问题

`docs/api-contract.md` 首版（601 行）提交时携带 5 个未定项（C1–C5）。契约是唯一接口事实源，**未冻结前任何调用方代码不得合入**（路由者已按此纪律挂起 `/v1/*` 转发链路）。

PM 尚未在群里就 C1–C5 逐项裁决，因此本文目前是**提案**，不是生效裁决。契约本体仍写着「本版未定项（需 PM 拍板后才冻结）」，二者一致。

## 建议裁决（C1–C5）

| # | 问题 | 建议 | 理由 |
|---|---|---|---|
| C1 | `POST /api/groups` 是否自动签发第一个网关 key | 是，自动签发；明文**仅在该创建响应出现一次** | 建组即可用，一步到位；"明文仅一次"纪律不变 |
| C2 | `GET /api/stats/usage` 的 bucket 是否允许自动降级 | 允许自动降级，响应**必须回显实际 bucket**，前端只按回显渲染 | 防 7d×1m 万级空桶；回显即防漂移 |
| C3 | 日志是否加后端导出端点 | 不加，前端自行导出 | 与画师既有表述一致，后端零额外面 |
| C4 | 删上游 `force=true` 是级联软删还是硬删 key | 软删（`enabled=false` + `deletedAt`） | 保留历史日志外键完整性 |
| C5 | 手动录余额是否保护"不可覆盖模板查得值" | 不保护，手动录入总是优先并置 `balanceSource=manual` | 人工核对结果最可信；来源已由 `balanceSource` 透明标注 |

路由者已表态支持 C2、C4，对 C1 无异议但补充一条：签发响应里的明文 `gatewayKey` 必须与 `POST /api/auth/login` 的会话 token 同级纪律，在契约里注明"仅响应出现一次"。

> 补充订正：会话 token 自 v1.1 起走 `HttpOnly` Cookie，**响应体里根本不出现 token**（契约 §0.5）。所以"明文仅一次"目前只适用于 `gatewayKey`：`POST /api/groups` 与 `POST /api/groups/:id/keys` 两处，契约 §4 已写明。

## 生效后影响（当前**尚未**生效）

- 契约版本升至 **v1.0-frozen**：字段改动必须改契约并新增 ADR，任何一方不得单方面改字段。
- `/api/keys` 对象补 `deletedAt`；软删 key 不再出现在列表/统计/网关可用池，历史日志外键保留。
- `/api/logs` 的 `upstreamId`/`keyId`/`groupId` 过滤参数在关联资源被软删后仍可查（`?includeDeleted=true` 显式带出）。
- 路由者、画师自冻结起可接字段联调。
