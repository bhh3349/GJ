## 一、对 v1.0 需求的前端侧补充

原文档 §7 只给了页面清单，缺「页面状态」「实时口径」「权限可见性」「性能验收」。补以下四类。

### 1. 页面级需求（每页必须有 loading / 空态 / 错误态 / 刷新）

| 页面 | 补充要求 |
|---|---|
| 仪表盘 | 4 个指标卡（QPS、成功率、今日 token、总余额）+ key 健康灯列表。首次进入骨架屏，WS 断线时卡片右上角显示「已断开·重连中」，不显示过期数字当实时值 |
| 上游管理 | Base URL 增删改；删除需二次确认并提示「将同时禁用其下 N 个 key」；URL 校验（必须 http(s):// 且不能以 `/` 结尾除非根路径） |
| Key 管理 | 列表默认只显示后 4 位；支持按上游 / 分类（token-plan・余额）/ 启用状态 筛选；余额列对 token-plan 显示「套餐」而非金额；支持批量禁用；余额单元格支持就地编辑（手动录入） |
| 用户组 | 建组、发/重置网关 key（**明文只在创建时弹窗展示一次**，之后只能重置）、配额表单（RPM / TPM / 日上限），配额留空 = 不限 |
| 模型档案 | 卡片列表 + 筛选（上游 / 类型 / 能力标签 / 关键词）；详情内展示可用 key 列表与价格；价格缺失时显示「—」而不是 0 |
| 统计 | ECharts 图表：按时间维度的 token 曲线、按 key / 上游 / 用户组 的分布；时间范围切换（1h / 24h / 7d / 自定义）；图表可导出 CSV |
| 日志 | 调用记录查询（时间范围 + 用户组 + 模型 + 状态 + 上游 key 后4位），分页，行展开看详情；key 一律脱敏展示 |

### 2. 实时性需求（明确口径，替换 v1.0 的「实时看板」一句带过）

- 通道：WebSocket 推送，**前端不轮询**；WS 地址与鉴权方式待「管家」定（见 §三 依赖项）。
- 推送频率：指标类 1s 一档，key 健康状态变化时立即推。
- 断线策略：指数退避重连（1s → 2s → 4s → max 15s），重连成功后自动全量刷新一次，避免缺口。
- 口径必须由后端给「时间窗口」字段（如 `window: '60s'`），前端不自己按本地时间猜 QPS，否则数字对不上。

### 3. 权限与安全（前端侧）

- 管理后台登录鉴权：未登录跳登录页；token 过期统一拦截 → 跳登录，不弹裸错。
- 数据隔离：A 组登录后，菜单与接口都只出现 A 组资源；前端不靠隐藏菜单做隔离，后端必须拒绝越权请求（前端只做体验层）。
- key 展示：任何位置（列表 / 详情 / 日志 / 图表 tooltip / 导出）都只出现后 4 位；**前端不缓存 key 明文**，创建弹窗关闭即从内存丢弃。

### 4. 性能与质量验收（对应「首屏 < 2s、所有操作有反馈」）

- 首屏：生产构建 + 本地后端，仪表盘首屏 LCP < 2s（目标 1.2s）；管理面路由级代码分割，图表库（ECharts）按需引入、不阻塞首屏。
- 反馈：任何写操作（新增 / 编辑 / 删除 / 启用禁用 / 同步模型 / 查余额）都必须有：按钮 loading → 成功 toast / 失败 toast（展示后端 `{code, message}` 中的 message，code 用于前端分支提示）。
- 长任务（模型同步、批量查余额）返回任务态可轮询的进度，不用「假进度条」。
- 禁止假数据：图表与列表在生产构建里不允许存在 mock 兜底；后端无数据就是空态，接口失败就是错误态。

## 二、设计标准（前端自定，PM 归档即可）

- 深色主题：AntD `theme.darkAlgorithm` + 自定义 token（背景分层 / 主色 / 语义色），语义色固定：成功=绿、失败=红、冷却=琥珀、禁用=灰。
- 图表配色统一从主题 token 取，不硬编码十六进制；同一指标在仪表盘与统计页颜色一致。
- 不使用原生 `<select>`：下拉一律用 AntD `Select`（可搜索）；数字输入带单位后缀（ms / 次）。
- 响应式：≥1440 三栏、1024–1440 两栏、<1024 折叠侧栏；表格横向滚动不换行。

## 三、前端对后端的字段依赖（不要求实现细节，只要求契约里有）

这些字段缺失会直接导致页面做不出来或只能造假数据，请「管家」在 `docs/api-contract.md` 里明确：

1. 列表统一分页结构：`{ items, total, page, pageSize }`；错误统一 `{ code, message }`。
2. Key 对象需含：`id / upstreamId / maskedKey(后4位) / category(token-plan|balance) / enabled / balance(分,int,可空) / balanceUpdatedAt / health(status: healthy|cooling|disabled) / lastFailureReason / todayTokens`。
3. 上游对象需含：`id / name / baseUrl / keyCount / enabled / totalBalance(分,int)`；余额查询模板是否可下发，以及**模板编辑页需要哪些字段**（url/method/headers/parse）。
4. 模型档案需含：`name / upstreamId / type(chat|embedding|image|audio|rerank) / capabilities[](stream|function_call|vision|json_mode) / contextLength / price{inputPer1k,outputPer1k}(分,int,可空) / availableKeyIds[]`。
5. 统计 `GET /api/stats/usage` 需支持 `groupBy=(key|upstream|group|model)`、`from/to(ISO8601)`、`bucket(1m|5m|1h|1d)`，返回序列化好的时间轴，前端不二次聚合。
6. 实时通道 `WS /api/stats/live` 的消息结构（类型 + 载荷 + 窗口口径）需在契约里给出示例，避免联调时双方各自猜。
7. 用户组需含：`id / name / gatewayKeyMasked / rpm / tpm / dailyQuota / todayUsage`，其中配额为 `null` 表示不限。
