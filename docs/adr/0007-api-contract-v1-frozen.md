# 7. API 契约 v1.0 冻结与 C1–C5 裁决

- 状态：已接受
- 日期：2026-10-06
- 决策者：管家 · 管理后端（提案）、PM（拍板）

## 背景与问题

`docs/api-contract.md` 首版（601 行）提交时携带 5 个未定项（C1–C5）。契约是唯一接口事实源，未冻结前任何调用方代码不得合入。PM 逐项核验后裁决如下。

## 决策（C1–C5）

| # | 问题 | 裁决 | 理由 |
|---|---|---|---|
| C1 | `POST /api/groups` 是否自动签发第一个网关 key | **是，自动签发，明文仅创建响应出现一次** | 建组即可用，一步到位；"明文仅一次"纪律不变 |
| C2 | `GET /api/stats/usage` 的 bucket 是否允许自动降级 | **允许降级，响应必须回显实际 bucket，前端只按回显渲染** | 防 7d×1m 万级空桶；回显即防漂移 |
| C3 | 日志是否加后端导出端点 | **不加，前端自行导出** | 与画师既有表述一致，后端零额外面 |
| C4 | 删上游 `force=true` 是级联软删还是硬删 key | **软删（`enabled=false` + `deletedAt`）** | 保留历史日志外键完整性 |
| C5 | 手动录余额是否保护"不可覆盖模板查得值" | **不保护，手动录入总是优先并置 `balanceSource=manual`** | 人工核对结果最可信；来源由 `balanceSource` 透明标注 |

## 影响

- 契约版本升至 **v1.0-frozen**，自此为唯一接口事实源：字段改动必须改本契约并新增 ADR，任何一方不得单方面改字段。
- `/api/keys` 对象补 `deletedAt` 字段；软删 key 不再出现在列表/统计/网关可用池，历史日志外键保留。
- `/api/logs`、`/api/keys` 列表过滤在关联资源被软删后仍可查（`?includeDeleted=true` 显式带出）。
- 路由者、画师自本 ADR 起可接字段联调，调用方代码以冻结契约为唯一依据。
