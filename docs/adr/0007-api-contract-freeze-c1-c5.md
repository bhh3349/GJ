# 7. API 契约 v1.0 冻结与 C1–C5 拍板

- 状态：已接受
- 日期：2026-10-06
- 决策者：PM（核验 `docs/api-contract.md` 首版 601 行后拍板）

## 背景与问题

`docs/api-contract.md` 首版（管家交付，23 KB / 601 行）覆盖管理面 REST + WS、错误码总表、画师 §三 7 条字段依赖对照、网关面边界。PM 逐节核验：类型口径（分/int/ISO8601 UTC/bool）、余额三口径防造假字段（`balanceUnknownKeyCount` 未知≠0）、key 明文纪律（请求体进入即加密、响应只有 `maskedKey`、网关 key 仅创建/重置时出现一次）、`PUT /api/keys/:id/balance` 中 `0` 与 `null` 语义分离、分页上限 200、`REVISION_MISMATCH` 乐观锁——均与既有决议一致。§11 留 5 个待拍板项（C1–C5），冻结前必须收敛。

## 决策

**`docs/api-contract.md` 即日冻结为 v1.0-frozen。** C1–C5 拍板如下：

| # | 问题 | 拍板 | 理由 |
|---|---|---|---|
| C1 | 建组是否自动签发第一把网关 key | **采纳管家倾向：自动签发**，响应额外带 `gatewayKey` 明文仅此一次 | 建组即可用，避免"建组→发 key"两步操作；明文纪律已有双保险（sha256 落库 + 前端不缓存） |
| C2 | `bucket` 跨度大时是否自动降级 | **采纳：允许后端自动降级，响应回显实际 `bucket`**，前端按回显渲染 | 与"后端带时间窗口字段"口径一致；前端禁止本地自算 |
| C3 | 日志导出端点 | **采纳：不加端点**，前端拿 `/api/logs` 自行拼 CSV | 画师已按此表述；后端不加无契约端点 |
| C4 | 删上游 `force=true` 是级联软删还是硬删 | **采纳：软删**（`enabled=false` + `deletedAt`），保留历史日志外键 | 硬删会断审计与用量日志外键；密文 key 留库无泄露面 |
| C5 | 手动录入余额是否阻止覆盖模板值 | **采纳：不保护**，手动录入总是优先并置 `balanceSource=manual` | `balanceSource` 字段本身就是来源可追溯机制，无需再叠一层拒绝逻辑 |

- 契约头状态改为 `v1.0-frozen (2026-10-06)`，§11 由"待拍板"改为"已拍板（见 ADR-0007）"。
- 后续任何字段级改动：改 `docs/api-contract.md` + 新增 ADR，四方同步后生效；未冻结改动不得写调用方代码的约束自冻结起转为"以冻结版为准"。

## 影响

- 正面：画师可按 §三 7 条字段依赖接线联调；路由者 M1 与管家 M2 可并行推进，以契约为准接口先行。
- 门禁：已核验 `pnpm-workspace.yaml` 白名单（better-sqlite3、esbuild）——vite 构建链经 esbuild 已覆盖，AntD 图标为纯 JS 无构建脚本，**无需新增条目**；冻结不引入门禁变更。
- 协作：三方共用一个工作树导致切分支互踩（实测：HEAD 在 `dev/gateway` 时工作树混有 `src/db/`、`src/security/`、`web/` 等多方未提交文件）。分支协作纪律在群内下达并记录于此：`main` 只进快进合并；各自在**自己的目录**提交并推**自己的分支**，不改工作树 HEAD 的分支指向；仅管家可切 HEAD（提前 1 分钟群内预告）。

## 补充（2026-10-06，PM 拍板：分支 / 工作树纪律）

- 采纳**一人一 worktree**：各方在 `.worktrees/<name>` 建自己的链接工作树（目录已在 `.gitignore`），在各自分支提交，不移动主工作树 HEAD 的分支指向。
- `main` 只进**快进**合并；`dev/infra` / `dev/gateway` / `dev/web` 的合流由管家执行并复验门禁。
- 仅**管家**可切主工作树 HEAD，切换前 1 分钟群内预告。
- 收口记录：`dev/gateway`（`87b9a58`）已并入 `dev/infra`（合并提交 `c135664`），主工作树 HEAD 落回 `dev/infra`。
