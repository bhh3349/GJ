# 通用开发守则 v1.0

> 跨项目可复用的 AI×AI / AI×人 协作软件开发规范。
> 新项目启动时，把本文件放进仓库 `docs/`（或根目录），全员照此执行，无需再口头逐条提醒。
> 项目特有内容（具体接口契约、具体配置口径）另立《开发约束》/《API 契约》文档，不写入本文件。

---

## 0. 文档定位

- 本文件只收**跨项目可复用的纪律与硬约束**，不收一次性任务、具体提交哈希、具体配置值。
- 目标是"丢文档即对齐"：新成员/新项目读一遍就能进入协作状态，减少口头提醒。
- 发现新的可复用经验，走版本化修订（v1.0 → v1.1），不悄悄覆盖。

---

## 1. 协作通信规则（最高优先级）

1. **唯一可靠的通信方式是 `@对方名字`。** 系统只把消息路由给被 @ 的人；不 @ 等于没发，对方很可能看不到，链路就断了。
2. **四类必须 @ 的场景**：派单（要对方执行）、求确认（要对方回答）、要答案、要拍板。正例：`@路由者 请接手线 B`；反例：只写"路由者去把 CI 补了"而不 @。
3. **不替别人干活。** 需要谁执行就点名交给谁；不代做，也不嘴上说"我指挥不了别人"。
4. **一个消息可 @ 多人**，但被 @ 的每个人都应明确自己在这条里要做什么；不相关的不要 @，避免噪音。
5. **收尾/无动作不带 @。** 结论已达成、对方陈述无需回应时，直接结束，不陷入无意义循环。
6. **人机同样适用**：需要人拍板/回答时，明确把问题抛给具体的人。

---

## 2. 接口先行（契约优先）

1. 涉及多模块协作的 REST / 内部接口，**先出契约文档，再写实现**。
2. **契约未定 / 未确认时，不写调用方代码**；契约有疑问先找 owner 对齐。
3. 跨项目统一约定：
   - 错误码：统一 `{code, message}`，`code` 用语义化枚举（如 `KEY_EXHAUSTED`、`QUOTA_EXCEEDED`）。
   - 时间：ISO8601，统一 UTC。
   - 金额：以最小单位整数传递（分），不用浮点。
   - 计数（token / 配额等）：`int`。
4. 跨模块边界：内核模块**不得反向 import** 管理层/存储层（如 gateway 不得 import db/api）；适配器集中放在 wiring 层。
5. 热路径零同步 DB 写；写操作走单写者原则。

---

## 3. 契约冻结与变更管理

1. 契约冻结后，任何字段 / 形状变更必须**双轨**：改契约文档 + 记 ADR（架构决策记录）。
2. 既有实现漏记 → 走"勘误"表头**补记，不升版**；冻结版本号不因补遗变更。
3. 表外未登记码统一走 `default` 退避，不得让前端实现成"按码白名单"。
4. 变更前先找 owner 确认口径；**不得擅自夹带**（尤其门禁扩容、脚本增删等契约面变更）。

---

## 4. 工程硬约束（不可妥协）

1. **敏感信息永不落盘**：真实写入路径 + 存储文件（含 wal/shm）裸字节扫描断言，缺一不可。
2. **禁止假数据 / 前端 mock 冒充真接口自测**：DoD（验收定义）必须走真实接口。
3. **关键配置（密钥等）缺失或非法 → fail-fast 拒绝启动**，不得带病运行。
4. **配置解析收紧**：整数环境变量只接受 `^-?\d+$`（有限）；`0x10` / `1e3` 之类直接拒绝。
5. **优雅退出有固定顺序**：先关 flush/镜像/密钥，再关库，且必须关在库关闭之前。
6. **确定性**：生产与测试不得依赖真实 timer 竞态。

---

## 5. 门禁与 CI（四闸）

1. **冻结四闸**：`typecheck` / `test` / `build` / `check:secrets`。不得私自增删、换名、拿别的脚本顶替。
2. **build 闸必须断言产物存在**（如 `dist/server.js`），只 `exit 0` 不够——tsc 配置失误导致零 emit 也会假绿。
3. `typecheck`（`--noEmit`）与 `build`（build 配置）**不是同一份配置**，不是冗余，两者都保留。
4. `check:secrets`：**0 命中且 0 文件判 FAIL**；每条规则必须有正对照 fixture 证明能命中。
5. **平台相关行为必须在目标平台真实验证**（如 SIGTERM 优雅退出顺序，Windows 无法验证 → 需 Linux CI）。
6. CI 步骤**顺序依赖显式声明**：build 在前、依赖 `dist/` 的冒烟在后、同 job；缺产物会假红。

---

## 6. 测试纪律

1. **消除真实 timer 竞态**：用 fake timers（`autoTick:false` + `tickNow()` / `advanceTimersByTimeAsync`）+ 显式拍屏障。
2. 否定断言用拍屏障推进时间后再断言，避免"还没等到就通过"。
3. 任何测试失败：**当场留日志 + 用例名**，不得裸红。
4. 关键场景写反向对照（负例），先证明转红、再还原，确保断言本身有效。
5. 只换阶梯不换封顶：收紧配置不得顺带改掉已冻结的默认语义。

---

## 7. Git 纪律

1. 主分支**线性历史、0 merge commit**。
2. 多 worktree 分支：**有专属 worktree 的分支禁裸 `update-ref`**，用 `merge --ff-only` / `checkout` / `reset`。
3. 合流用 CAS（如 `update-ref` 三参、全名 `refs/heads/...`），执行后核 `tree`；`status --porcelain` 为空才报"收口"。
4. 每个里程碑设**稳定基点**（单点 commit），后续可安全回溯、可作下阶段基线。
5. 删除脚本 / 语义名是冻结口径：删掉后不得再当门禁引用；被引用前先确认没有依赖方。

---

## 8. 里程碑与验收

1. 每里程碑**验收标准量化**（成功占比、P99 延迟、首屏时间、测试数等），不留模糊词。
2. 验收证据**落案**（CI run 链接、测试通过数、扫描字节数），不留口头"应该好了"。
3. 阻塞项显式**归属 owner**，拍板人明确；外部托管、仓库公开/私有、凭据等属 owner 级决策，owner 可授权定档但须记录。

---

## 9. 角色分工

1. 各角色职责边界写入角色定义；跨边界改动先找 owner 确认，不在契约未定时写调用方代码。
2. **PM 拍板推进、不写代码**；执行 agent 各守模块，接口经 owner 确认后落地。
3. 文档/脚本归属明确到人：别人名下的残留措辞不擅改，等 owner 授权单开。

## 附：本次沉淀来源（示例，非约束）

本守则从一次"多 Key 池化 OpenAI 兼容转发网关 + 管理后台"项目的完整开发过程（M0–M5、多 agent 协作、四闸 CI、多 worktree 分支、契约冻结）中提炼，去掉项目特有细节后形成以上通用条款。新项目可直接沿用，项目特有内容另立文档。
