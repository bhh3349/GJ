# ADR-0036：Base URL 的 `/v1` 与逐把 key 的管理面 —— 一个零新增端点的版本

- 状态：**已接受（2026-10-17，Bo 报「1panel 的管理界面没有发 key 的按钮，都是用户界面用户自己发 key。Base Url 地址也不正确」）**
- 关联：契约 **§4**（端点表 + key 形状 + 逐把管理面登记）、**§18**（URL 拼接责任那格 + 实现锚）、
  **§19.5**（公式那条，两行只差 `/v1`）、**§19.3**（掩码列表，"没有第二个明文读取面"）
- 车道：**`web/` 独占**（`src/**` 与 `src/gateway/**` 零改动、零新增端点、零 DDL、零新错误码）
- 触发：Bo 的一句话里其实是**三种不同的病**：一个**前端少了一段字面量**、
  一个**端点一直在但界面粒度不对**、一个**文案把 key 的前缀写错了**
- **验收时发现并当场修掉的第 4 病（P0，先于本 ADR 三个版本就存在）**：见下
  「验收实测：一次真跑抓住的东西」—— 决策 4 写的"本版最大风险是没人真的点过"
  在本版自己身上应验了。

## 背景：三张不同的脸，一个症状「不好用」

### 1. 「Base URL 不正确」——服务端没算错，前端少抄了 `/v1`

把"不正确"拆成两个可能：host 算错了，还是路径不全。实测否掉了第一个：

```
GET /models         → 404        （服务根 + 路径）
GET /v1/models      → 401        （无 key；路由到了，鉴权挡下）
```

`404` 与 `401` 的差别就是**前缀是路由的一部分**。而 §18 的公式给的是**服务根**：

```
(publicHost ?? window.location.hostname) + ':' + portGateway     →  http://10.0.0.5:4000
```

于是管理面「接入信息」与消费面「接入与 key」两页把这个根当初"Base URL"摆出来。
用户照着抄进 ChatGPT-Next-Web / LobeChat，第一个响应是 404 ——
**站点自己给的地址打不通，是最容易让人怀疑整台网关坏了的失败形状**：他不会想"少了个 /v1"，
他会想"这东西没做成"。

同时它也解释了为什么这个 bug 能活这么久：**全仓唯一把正确形状打出来的地方是启动日志**
（`src/server.ts` 那行 `网关 Base URL: http://…:4000/v1`），而日志不给用户看。

### 2. 「没有发 key 的按钮」——按钮在，但只长在"整组"这一层

服务端**一个字段都不缺**：`GET /api/groups/:id/keys`（唯一给出 `:keyId` 的读面）、
`POST …/keys`（签发）、`POST …/:keyId/reset`（重置，同事务删旧）、`DELETE …/:keyId`（吊销）
四条自 §4 起就在，`src/api/api.spec.ts` 里早有整套用例（列表不含明文 / 第一项等于 `Group.gatewayKeyMasked` /
按 id 重置可用 / 跨组 404 不泄漏存在性 / 吊销后 `keyCount` 同步且不再出现）。

缺的在 `web/`：

- `GroupsPage` 每行只显示**一个** `gatewayKeyMasked` + 「共 N 把」——N > 1 时
  界面上分不清哪把是哪把；
- `groupsApi.resetKey` / `groupsApi.removeKey` **零调用方**（`git grep` 可查）：
  两个函数写好了、类型也有了，没有任何一行代码碰过它们；
- 于是"重置 / 吊销某一把"这件**服务端已经支持**的事，在管理面上没有出口 ——
  这正是 Bo 说的"没有发 key 的按钮"：他要的不是"再发一把"（那个按钮一直在），
  是**1panel 那种"能看见自己有几把、能对其中一把动手"的面**。

### 3. 「以 `sk-` 开头」——一句错到会误导人的文案

消费面 §19.5 那页写着「密钥用下面列表里的任意一把 —— 以 `sk-` 开头的完整串」。
而网关 key 的前缀是 **`gw-`**（`src/db/ids.ts`：*用 `gw-` 前缀而非 `sk-`：
这是我们自己签发的凭据，不该长得像上游 key*）。照那句话去下面的列表里找 `sk-` 开头的串，
**得到的是空集**：用户手里那把 key 明明在，界面却说它不是这个东西。
（契约正文此前**从未**登记过网关 key 的形状，只在 §12 的脱敏正则里出现过 `gw-…` —— 所以这句错话没有任何一处可以对照。）

## 决策

### 1. `/v1` 是**前端公式的固定后缀**，不是新的服务端字段

给 §18 加一个 `gatewayBaseUrl` 字段是**看起来最省事**的做法，也是本版明确不做的：
ADR-0028 决策 2 的理由一字未变 —— 服务端不知道公网 host（`PUBLIC_HOST` 是部署事实），
`0.0.0.0` / `127.0.0.1` 都是监听语义，**拼 URL 必然猜错**。真正的病因不是"服务端没给"，
而是"前端给了、少一段"。

所以：

- **公式加后缀**：§18 / §19.5 的拼接结果 + `'/v1'` = 填进客户端的 Base URL；
- **`/v1` 只写一处**：前端一个拼装函数里。四处各手抄一遍 `/v1` 的失败形状是
  "哪天网关路径前缀变了，改三处漏一处"——而漏的那一处**不会红**（它只是给用户一个 404 的地址）；
- **服务根仍然展示**：它服务静态页与 `/api/*`，是有用的信息，只是**不该被叫 Base URL**。

**为什么这不是"第二个公式"**：§19.5 那条禁令（不新开 `/api/console/access-info`）禁的是
**两份可能漂移的事实源**。这里是同一份事实（同一个端点回同样三个字段）+ 同一段固定字面量，
漂移的空间只有"/v1 拼上了没有"，而那正是被这一版**收进一个函数**的东西。

### 2. 逐把 key 的管理面 = 组行上的一个抽屉，四条既有端点原样用

入口加在 `GroupsPage` 那一行的「key 管理」上，抽屉里：

| 动作 | 端点 | 界面上必须说出来的代价 |
|---|---|---|
| 列 key | `GET /api/groups/:id/keys` | 只显示掩码；**没有"显示明文"** |
| 签发新一把 | `POST /api/groups/:id/keys` | 明文当场展示**一次** |
| 重置某一把 | `POST …/:keyId/reset` | 确认框里明写「**旧 key 立即失效**」 |
| 吊销某一把 | `DELETE …/:keyId` | 硬删、不可恢复；**只解绑不了**（网关 key 就是凭据本身） |

三条纪律：

1. **没有"显示明文"按钮**。没有任何端点能取回明文（§4 铁律 / ADR-0006），
   按钮点了也只能失败 —— **比没有按钮更坏**（§19.3 同一句）。抽屉里能给的只有掩码，
   要明文只有两个动作：签发、重置，两者都会当场弹那一帧的明文。
2. **吊销 / 重置成功后就地改这一行，不整页刷新**。与 `UsersPage`「归属组」就地改、
   `GroupsPage` 删除后 `list.reload()` 同一层意思：让操作者自己按 F5，
   等于把"删没删掉"变回猜谜（Bo 第二条投诉就是这件事的另一个面）。
3. **每次给明文的地方，旁边就是带 `/v1` 的地址**。抄 key 的人下一个问题永远是"填哪儿"，
   而那正是这一版要修的另一半 —— 两件事分开修，等于把"地址对、key 没有"的挫败留给下一次。

**为什么是抽屉不是新页面**：它是**某一个组**的属性，页面级导航会把"我在看哪个组"变成
URL 状态、刷新后要还原、权限与加载态都要重来一遍；而抽屉的既有先例在本仓已有四处
（`SupplierBatchDrawer` / `SupplierAccountDetailDrawer` / `ModelDetailDrawer` 等）。

### 3. 文案订正：`sk-` → `gw-`，并把形状登记进契约

前端那一句改为 `gw-`，同时**在契约 §4 把网关 key 的形状正式登一笔**。
后者不是顺手：这句话错了一年没人发现，恰恰是因为**没有任何一处写着正确形状**。
把形状写进契约，下一处措辞才有东西可对照 —— 判据落在"能对照的文本"上，不是"某人记得"。

### 4. 本版**不动服务端**，所以没有"变异验证"可做

`src/**` 一个字节不改 ⇒ 后端四道门禁的职责是**证明我没碰过它**（全绿 + 计数不变），
而不是证明新行为。本版的判据只能是**真跑一遍**（见下）。这一点必须写下来：
**一个 UI 版本最大的风险不是"改错了"，是"没人真的点过"** —— ADR-0034 遗留 7 与
v1.15.5 的教训（P0 在第三版才被发现，因为"手工登一次"那条纪律被跳过了两次）就在这里。

## 判据

本版 `web/` 无 test runner（ADR-0034 遗留 7 / ADR-0035 遗留 6 同一条），所以判据是
**一次真跑**，逐条写下来（跑过才算，见「实测验收」）：

| 用例 | 钉住什么 |
|---|---|
| 管理面「接入信息」显示的接入地址以 `/v1` 结尾 | Bo 的第一句原话 |
| 消费面「接入与 key」的 API 地址以 `/v1` 结尾，且该串可复制 | 用户抄走的那个串必须能打通 |
| 组行「key 管理」列出该组全部 key（掩码 + 创建时间） | 逐把视野 |
| 列表里的第一把掩码 = 组行那个 `gatewayKeyMasked` | 两个面说的是同一件事（契约 §4 已钉：排序固定、第一项恒等） |
| 重置某一把 → 弹一次性明文；**旧明文打 `/v1/models` 立刻 401**、新明文 200 | 重置是真重置，不是一个好看的弹窗 |
| 吊销某一把 → 抽屉里那一行**当场消失**，且**不刷新整页** | Bo 第二条投诉的同一纪律 |
| 吊销后同一把 key 打 `/v1/models` → 401 | 吊销是真吊销（不是列表过滤） |
| 抽屉里**没有**"显示明文"入口 | 不给一个只会失败的按钮 |
| `GET /api/access-info` 响应体**仍是那 7 个字段** | 本版没偷偷加字段（`git diff src/` 应为空） |

## 验收实测：一次真跑抓住的东西

上面那张表是**计划的**判据。真跑之后，它抓到了三件计划里没写的事 —— 这一段就是
"决策 4 说本版最大的风险是没人真的点过"的实证，逐条记下来：

**① 建组把整页打进错误边界（P0，先于本版三个版本就存在）**
`POST /api/groups` 的 `gatewayKey` 是**嵌套对象**（`{id, gatewayKey, maskedKey, createdAt}`），
而 `web/src/api/types.ts` 把它声明成 `gatewayKey: string`，`GroupsPage.onCreated` 直接把
`created.gatewayKey` 交给弹窗 → React 抛 `Objects are not valid as a React child`，
**建完组整页变成"界面渲染出错"**。Bo 的原话「功能做了但是做了一半，完全没法用」在这个点上
是**字面成立**的：建组是整个产品的主入口，而它一按就崩。
**为什么四道门禁全绿还是漏了**：类型声明与服务端实现不一致时，编译期只能验"用的人和声明一致",
验不了"声明和服务端一致"；而契约此前**只写"额外带 `gatewayKey` 明文"，从未写过它是对象**——
一份没写明形状的响应，前端只能猜。修法：类型改成 `GroupKeyIssued`（与 §4 另两行同一个类型，
不是第三个 interface），并把这条形状对照补进契约 §4（连带把 `…/:keys` 的顶层四格并排写出）。
**这一条同时说明**：`pnpm typecheck` 绿 ≠ 类型是对的，只等于"内部自洽"。

**② Base URL 给出来了，但建组路径没带上**
`baseUrl` 只传给了「签发新一把」那条路径，`onCreated` 漏了 —— 于正好是**最常见的那条路**
（新建用户组 = 立刻拿到第一把 key + 它的地址）少了一行地址。真跑时对着弹窗一眼看出。

**③ 三处 `**加粗**` 的 markdown 语法被当普通文本渲染**
`GroupKeysDrawer` 两处（本版新写）+ `SupplierAccountsPage` 一处（既有），
JSX 里写 `**字**` 会**原样把星号显示给用户**。全库扫一遍（脚本按注释/字符串状态机扫描，
不看行首）确认只有这三处，已改成 `<Text strong>`。这不是本版引入的独有毛病，
但本版新写的那两处是本版的责任。

**最终逐条实测结果**（服务端 `dist/server.js`、`ADMIN_WEB_DIST=web/dist`、真实浏览器）：

| 判据 | 实测 |
|---|---|
| 管理面接入页接入地址以 `/v1` 结尾 | ✅ `API 地址 http://127.0.0.1:4000/v1` + 独立的「服务根 `http://127.0.0.1:4000`」 |
| 组行「key 管理」列出该组全部 key | ✅ 抽屉列出掩码 + 创建时间 + 逐把「重置 / 吊销」 |
| 列表第一把掩码 = 组行 `gatewayKeyMasked` | ✅ 组行 `****eu6Z`、列表第一项 `****eu6Z` |
| 重置 → 旧明文立刻 401、新明文 200 | ✅ 旧 `gw-Ljh3sBs0p…eu6Z` → **401**；新 `gw-mVo00dTXU…6WX6` → **200** |
| 重置不动同组其它 key | ✅ 兄弟 key `gw-wvwYk4F…8yx0` 全程 **200** |
| 吊销 → 行当场消失且**不刷新整页** | ✅ 行数 2→1；页面一个 `no-reload-<ts>` 内存标记**存活**（证明没重载） |
| 吊销后那一把打 `/v1/models` → 401 | ✅ **401**；同组剩余那把 **200** |
| 组行派生值在吊销后被服务端重新校准 | ✅ 组行掩码由 `****eu6Z` 变 `****6WX6`、`共 1 把`（前端不自己推算） |
| 抽屉里**没有**"显示明文"入口 | ✅ 抽屉按钮只有「重置 / 吊销 / 刷新 / 签发新 key」 |
| 建组弹窗带明文 + 带 `/v1` 的 Base URL | ✅ ①/② 修完后实测两样都在 |

## 遗留（不粉饰）

1. **`web/` 仍然没有自动化测试**。本版新增的抽屉、措辞、`/v1` 后缀**全部靠手工验收兜底**。
   这是本仓第 N 次在同一条遗留上做交付（ADR-0034 遗留 7 起），本轮**不再重复"下次补"的承诺** ——
   真正该做的是给 `web/` 配一个 runner（`vite` 已在，只差 vitest + jsdom 的配置与一两个 smoke），
   而那是独立一版的工作量，塞进本版会让"Base URL 错在哪"这个明确的小修变成一次前端基建改造。
2. **`/v1` 是硬编码的字面量**（拼装函数里）。网关路径前缀目前是契约冻结的一部分
   （§10），所以硬编码与现状一致；但若哪天出现"可配前缀"，改动面是**前端所有引用点**，
   而不是一个配置项 —— 本版把它收在一个函数里，是把这个代价压到最小，不是消灭它。
3. **抽屉里没有批量操作**（全选重置 / 全选吊销）。Bo 报的是"看不见每一把"，
   而批量吊销是**一次点击废掉 N 把凭据**的形状，值得单独一条 ADR（权限、二次确认、误操作的挽回面）。
4. **`GroupKeyResetResponse`（`web/src/api/types.ts`）此前少了 `id` / `createdAt`**，
   而契约 §4 与实现都回四格。本版顺手补齐类型 —— 但因为前端此前零调用方，这个漂移
   **从未产生过错误行为**；写在这里是记账，不是邀功。
5. **重置不保留旧 key 的任何痕迹在界面上**。旧 key 立即失效、行被替换，
   审计里只有 `gateway_key.reset` + 新掩码（旧掩码只存在于上一条 `gateway_key.issue` 里）。
   这是 §4 既有口径（"改法是删旧插新"），本版不动它，但**用户不会从抽屉里看到"上一把是谁"**——
   要追只能去审计页。
6. **管理员的种子组密钥仍在启动日志里出现过一次**（ADR-0035 遗留 1）。
   本版把 Base URL 补全之后，那句"从日志里抄 key"的引导**更容易照做了** ——
   这是遗留 1 代价的放大，登记在此而不是留给以后发现。
7. **本版最刺眼的一条遗留：一个"建组即崩"的 P0 活到了现在**。
   它不在本版引入，但**本版之前的每一次交付都声称"四闸全绿"**，而四道门禁里
   **没有一条会去点一下按钮**（`web/` 无 runner，ADR-0034 遗留 7）。这不是"下次注意"能解的：
   只要 `web/` 没有一条 smoke（哪怕就是"登录 → 建一个组 → 断言弹窗里有一个 `gw-` 开头的串"），
   同一类 bug 就会继续以"编译绿、运行崩"的形状活着。本版**再次不承诺"下次补"**（同遗留 1），
   只把事实登记清楚：**`pnpm typecheck` 绿只证明内部自洽，不证明类型与契约一致**。
8. **契约只写"带某个字段"、不写"什么形状"，就是这个 P0 的根因**。
   本版在 §4 补了对照文本（两行明文位置不同形），但这是**事后补的**；
   全库还有多少"字段写了、形状没写"的地方没有系统盘点过 ——
   真正该做的是让契约片段可以被机器比对（或至少让前端类型从契约生成），那是独立一版的事。
