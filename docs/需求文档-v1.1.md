## 二、通用约定（冻结候选）

1. **错误体分离**：
   - 网关面 `/v1/*` → OpenAI 错误格式 `{error:{message,type,code}}`（保证现成 SDK 兼容）
   - 管理面 `/api/*` → `{code, message, details?}`
2. **管理面错误码枚举**：`INVALID_KEY / DUPLICATE_MODEL / TEMPLATE_PARSE_FAILED / BALANCE_UNKNOWN / KEY_EXHAUSTED / QUOTA_EXCEEDED / UPSTREAM_UNAVAILABLE`；网关侧另有 `NO_AVAILABLE_KEY`(503) / `UNSUPPORTED_ENDPOINT`(501)
3. **分页**：`{items, total, page, pageSize}`，`limit` 默认 20、上限 200
4. **脱敏**：任何接口/日志/导出只回 `****后4位`；上游 key 密文 `v1:iv:tag:ct` 单字段存储；网关 key 存 `sha256+pepper`；任何接口不回明文与密文
5. **脱敏范围覆盖**：列表、详情、日志、图表 tooltip、CSV 导出、前端内存（创建弹窗关闭即丢弃明文）

## 三、统计与计量口径

1. usage 记录：`prompt/completion/total tokens`、延迟、状态、用户组、模型、上游 key（脱敏）、`x-request-id`
2. **估算**：上游无 usage 时按字符估算，落 `is_estimated=1`
3. **配额结算**：估算值计入 TPM/日配额；流式请求开始时按 `max_tokens` 预留 TPM，结束时按实际 usage 结算
4. **时区**：存 UTC；「今日」= 配置时区自然日（默认 Asia/Shanghai）
5. **保留**：调用日志默认 30 天，超期归档/清理可配；预聚合表 `usage_hourly`/`usage_daily` 支撑统计 API < 100ms
6. **不做**：prompt/completion 原文落库（隐私+体积），留开关默认关；不做余额实时轮询上游（余额走模板引擎+手动，网关只消费结果）

## 四、网关内核需求（负责人：路由者）

### 1. 智能路由与故障转移（修改 v1.0 §4）
- 选 key：过滤（模型匹配 + 启用 + 余额>0/套餐有效 + 不在冷却 + 并发未满）→ 排序（权重 → 剩余额度 → 上次失败时间）
- **换 key 仅限未向客户端写出任何字节前**；已开始输出后上游中断 → 不换 key，发送 SSE 错误事件后正常 `[DONE]` 关闭，按已产生部分 usage 计费
- 换 key 默认同上游内；跨上游可配置（默认关）
- 重试上限 3 个 key（可配）；stream 直通不缓冲

### 2. 失败分类与冷却（修改 §4/§6）

| 上游情况 | reason | 计入 key 失败 | 冷却策略 |
|---|---|---|---|
| 401/403 | `AUTH_INVALID` | 是 | 长冷却 30min + 告警；连续 N 次自动禁用 |
| 429 | `RATE_LIMITED` | 是 | 按 `Retry-After`，默认 60s，指数退避 |
| 402/余额不足 | `INSUFFICIENT_BALANCE` | 是 | 长冷却 + 余额告警 |
| 400/404/422 | — | **否** | 无，直接透传客户端 |
| 5xx | `UPSTREAM_ERROR` | 是 | 短冷却 10–30s |
| 连接/读取超时、ECONNRESET | `NETWORK` | 是 | 短冷却 15s |
| 客户端主动断开 | — | **否** | abort 上游，日志记 `aborted` |

- 探活用 `GET /v1/models`（零 token 成本）；冷却半开探测 1m→5m→15m→30m 封顶
- 冷却/阈值/并发/超时全部可配置

### 3. 限流与配额（修改 §5）
- RPM/TPM：**60s 滑动窗口**
- 日配额：按配置时区自然日；超限返回 429 + `Retry-After` + `x-ratelimit-*`
- 新增**每 key 并发上限 `maxConcurrency`**：超并发的 key 「暂不入选」，不算失败、不进冷却

### 4. 接口面（修改 §8）
- `/v1/chat/completions`（stream/非 stream）、`/v1/models`（档案模型并集 + `owned_by`）、`/v1/embeddings`
- 无可用 key：503 `NO_AVAILABLE_KEY`；未支持类型：501 `UNSUPPORTED_ENDPOINT`

### 5. 网关 key 存储（修改 §9）
- 网关 key 存 `sha256+pepper`（不可逆），列表只回后 4 位

### 6. 热路径与可观测（新增）
- usage 日志异步批量写（50 条或 200ms flush，退出 flush）；写失败降级本地 spool 文件；转发路径零同步 DB 写
- `x-request-id` 生成并透传上游、落日志
- `GET /internal/snapshot`：每 key in-flight/成败计数/冷却剩余/最近错误、上游熔断状态

### 7. 模型别名（新增）
- 「客户端模型名 → 上游真实模型名」映射表；`/v1/models` 返回并集；路由按映射匹配

### 8. 上游级熔断（新增）
- key 全挂时上游级熔断短路，避免每请求白试 3 次（连续失败短路 N 秒，可配）

### 9. 超时参数（新增）
- 连接超时 / 首字节超时 / 流内空闲超时 / 整请求上限，四项独立可配

### 10. 配置同步机制
- 共享 SQLite(WAL) + 网关进程内缓存 + 管理端变更事件（`change_log` 表 + revision 失效）+ 1s 轮询兜底 → 热路径零 DB 查询；配置热更新生效 < 1s
- key 健康状态（冷却/失败计数）为**网关运行态**，管理端只读展示 + 手动启停/恢复（单写者原则）

## 五、管理后端需求（负责人：管家）

### 1. 数据模型（v1.0 缺口：无任何表定义）
`upstreams` / `upstream_keys`（cipher, iv, tag, key_version, key_tail4, category, status, weight, balance_cents, balance_updated_at, cooldown_until, fail_count, last_error）/ `key_models` / `models` / `groups` / `group_keys` / `usage_logs` / `usage_hourly` + `usage_daily`（预聚合）/ `balance_snapshots`（余额历史，扣减曲线）/ `audit_logs` / `alerts` / `change_log`（配置变更事件）

索引：`usage_logs` 按 `(ts)`、`(upstream_key_id,ts)`、`(group_id,ts)`、`(model,ts)`

### 2. API 清单（在 v1.0 §8 五大资源上补齐）
- 新增：`/api/auth/{login,logout,me}`、`POST /api/upstreams/:id/balance-template/test`（dry-run：请求摘要+原始响应+解析结果，全脱敏）、`POST /api/keys/:id/test-balance`、`PUT /api/keys/:id/status`、`GET /api/logs`、`GET /api/stats/overview`、`GET /api/alerts`
- 原有：`/api/upstreams`、`/api/keys`、`PUT /api/keys/:id/balance`、`/api/groups`、`/api/models`、`POST /api/models/sync`、`GET /api/stats/usage`（`groupBy=key|upstream|group|model`、`from/to`、`bucket=1m|5m|1h|1d`，返回序列化时间轴）、WS `/api/stats/live`

### 3. 余额查询模板引擎（细化 v1.0 §1）
- 变量：`{key}` `{base_url}` `{key_tail4}`；`timeout_ms` 默认 5s、`retries` 默认 1
- 解析：JSONPath 子集 + **候选路径数组**（`["data.balance","data.data.balance"]`）+ 单位换算（元→分，四舍五入）
- 失败分类 network/timeout/parse/auth；**失败绝不覆盖已有余额**，只记 `last_error`
- AI 辅助填写：供应商文档 → AI 输出配置 JSON → 人工确认后生效；查不到的 key 手动录入
- 刷新走后台任务 + 手动触发，**永不进请求路径**

### 4. 统计聚合
- 按 key / 上游 / 用户组 / 时间（bucket）聚合，走预聚合表保证响应 < 100ms
- 「今日 token」与限流口径同源（见 §三）

### 5. 安全与一致性
- `MASTER_KEY` 必须 32 字节；**缺失/长度错拒绝启动，不静默降级明文**；`key_version` 预留轮换
- 上游 key aes-256-gcm 加密，明文永不落盘
- 管理后台 v1 单账号：密码 hash + 会话 token + 登录限速；除 `/api/auth/login` 外全部鉴权
- upstream/key/group 写操作全量落 `audit_logs`（who / what / before / after）
- 单写者原则：`cooldown/fail_count` 归网关；管理端写 key 递增 `revision` 触发网关缓存失效
- `alerts`：key 连续失败 N 次 / 余额低于阈值（对应仪表盘告警条，见 P10）

## 六、Web 前端需求（负责人：画师，详见 `docs/需求补充-前端-v1.1.md`）

### 1. 页面清单与三态（每页必须有 loading / 空态 / 错误态 / 手动刷新）
仪表盘、上游管理、Key 管理、用户组、模型档案、统计、日志，共 6+1 页：
- 仪表盘：QPS/成功率/今日 token/总余额四卡 + key 健康灯 + 告警条（P10）；WS 断线显示「已断开·重连中」，不拿过期数字当实时值
- 上游管理：删除二次确认并提示「将同时禁用其下 N 个 key」；URL 格式校验
- Key 管理：只显示后 4 位；按上游/分类/启用状态筛选；token-plan 余额列显示「套餐」；批量禁用；余额就地编辑
- 用户组：网关 key **明文只在创建时弹窗展示一次**，之后只能重置；配额留空 = 不限
- 模型档案：卡片 + 筛选（上游/类型/能力/关键词）；价格缺失显示「—」不是 0
- 统计：ECharts，时间范围 1h/24h/7d/自定义，`groupBy` 切换，CSV 导出
- 日志：时间/用户组/模型/状态/上游 key 后4位筛选，分页，行展开详情

### 2. 实时口径
- WS 推送不轮询；指标 1s 一档，健康状态变化即推；指数退避重连 1→2→4→max 15s，重连成功全量补刷
- **QPS 由后端带时间窗口字段（如 `window:'60s'`），前端不按本地时间猜**

### 3. 权限与安全（前端侧）
- 未登录跳登录页；token 过期统一拦截；A 组看不到 B 组资源（后端拒绝越权为准，前端只做体验层）
- key 明文不缓存，创建弹窗关闭即从内存丢弃；任何展示位置只出现后 4 位

### 4. 性能与质量验收
- 首屏 LCP < 2s（目标 1.2s）：路由级分包、ECharts 按需引入
- 所有写操作：按钮 loading → 成功/失败 toast（展示后端 message，code 用于分支）
- 长任务（模型同步、批量查余额）真进度，**不做假进度条**；生产构建禁止 mock 兜底
- 设计：AntD `theme.darkAlgorithm` 深色主题；语义色固定（成功=绿/失败=红/冷却=琥珀/禁用=灰）；下拉一律 AntD Select；响应式 ≥1440 三栏 / 1024–1440 两栏 / <1024 折叠侧栏

### 5. 前端字段依赖（已并入契约要求，见 §五.2）
列表分页结构、Key/上游/模型/用户组对象字段、stats `groupBy+bucket+时间轴`、WS 消息结构示例、`null` 配额=不限 —— 7 条以 `docs/api-contract.md` 字段级定义为准。

## 九、验收标准（量化版，替换 v1.0 §四）

| # | 标准 | PASS 判据 | 主责 |
|---|---|---|---|
| 1 | 轮询出量 | 2 上游 × 3 key，连续 60 次请求，每个健康 key 成功占比 ≥ 10% | 管家+路由者 |
| 2 | 故障切换 | 人为禁用 1 key 后，后续请求 0 次客户端可见错误；首字节前切换 P99 < 100ms；401/429/超时/进程 kill 四类故障演练客户端无感 | 路由者 |
| 3 | 性能 | TTFB 增量 P50 < 5ms（同机直连 vs 经网关对比）；压测下日志写入不引起 TTFB 抖动 | 路由者 |
| 4 | 看板实时性 | 任一 key 余额/用量变动后，Web 端 5s 内呈现新值（WS 推送） | 管家+画师 |
| 5 | 模型一致性 | `/v1/models` 返回集合与模型档案「已启用」集合逐项比对 0 差异 | 管家+路由者 |
| 6 | 数据可见 | Web 页能看每个 key 余额 + 今日 token 用量；管理 API 响应 < 100ms | 管家+画师 |

| 8 | 安全 | 密文存储 + 启动校验（无 MASTER_KEY 拒绝启动）；全链路只出现后 4 位 | 管家 |
